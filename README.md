# 🚀 Shadowrocket Config & Auto-Updating Rules

Готовая конфигурация и набор автоматически обновляемых правил для **Shadowrocket (iOS)**.

Проект появился благодаря работе Михаила — https://github.com/misha-tgshv.

За основу был взят его конфиг, который затем был значительно переработан и адаптирован под собственные сценарии использования.

Сейчас репозиторий развивается независимо и содержит собственную конфигурацию, структуру маршрутизации и наборы правил.

---

# 📱 Что это?

Основной сценарий — использование Shadowrocket в режиме **VPN-by-default**:

> VPN постоянно включён, а сервисы, которым VPN не нужен или мешает, автоматически работают напрямую.

Конфигурация построена на внешних `RULE-SET`, поэтому большинство изменений в списках применяется без необходимости вручную редактировать основной конфиг на устройстве.

### Основные задачи

- 🌍 весь неизвестный интернет-трафик по умолчанию направляется через **VPN**;
- 🇷🇺 российские сервисы работают напрямую;
- 🇨🇳 основные китайские сервисы работают напрямую;
- 🍎 системные сервисы и инфраструктура Apple работают напрямую;
- ▶️ YouTube принудительно направляется через VPN;
- 🎮 отдельные мобильные игры могут принудительно направляться через VPN;
- 🚫 реклама, аналитика и трекеры блокируются отдельным списком;
- 🏠 локальная сеть и системные адреса не ломаются при постоянно включённом VPN;
- 🔐 DNS-запросы обрабатываются через защищённые DNS-серверы.

# 📥 Установка

## VPN-by-default

Основной и единственный актуальный конфиг:

```text
https://cdn.jsdelivr.net/gh/MyNicknme/shadowrocket-rules@main/config/VPN-by-default.conf
```

### Логика маршрутизации

```text
LOCAL / LAN        → DIRECT
Ads & Trackers     → REJECT
YouTube            → PROXY
Mobile Games       → PROXY
Apple              → DIRECT
Russian Services   → DIRECT
Russia             → DIRECT
Google Core        → DIRECT
China Services     → DIRECT
2GIS                → DIRECT
RU / CN GeoIP      → DIRECT
Everything else    → PROXY
```

Главный принцип:

```text
FINAL,PROXY
```

То есть если трафик не совпал ни с одним специальным правилом, он автоматически отправляется через VPN.

Это позволяет постоянно держать Shadowrocket включённым без необходимости вручную переключать режимы маршрутизации.

# 🧭 Приоритет правил

Shadowrocket обрабатывает правила **сверху вниз до первого совпадения**.

Поэтому порядок `RULE-SET` имеет значение.

Конфигурация построена по следующей схеме:

```text
1. LOCAL / SYSTEM
        ↓
2. REJECT
        ↓
3. FORCE PROXY
        ↓
4. DIRECT SERVICES
        ↓
5. GEOIP FALLBACK
        ↓
6. FINAL,PROXY
```

Например, правила YouTube располагаются выше общих Google DIRECT-правил. Благодаря этому YouTube остаётся в `PROXY`, даже если часть его инфраструктуры пересекается с сервисами Google.

# 📂 Структура правил

Правила разделены на независимые `.list` файлы.

## 🟢 DIRECT

### Apple

Apple разделён на несколько уровней:

- `apple_useragent.list` — системные процессы iOS/macOS;
- `apple_domains.list` — домены Apple, iCloud, App Store и CDN;
- `apple_ip.list` — IP-сети Apple как fallback.

В DIRECT, в частности, входят:

- Apple system services;
- App Store;
- iCloud;
- Apple Music;
- Apple TV;
- Find My;
- Maps;
- Apple CDN;
- Apple NTP / time services.

Такой подход позволяет большинству Apple-сервисов использовать прямое соединение, что в некоторых сетях работает быстрее и стабильнее VPN.

### Russia

- `ru_services.list` — отдельные российские сервисы;
- `ru.list` — российские домены и правила.

Дополнительно используется:

```text
GEOIP,RU,DIRECT
```

### China

`china_direct.list` содержит основные китайские сервисы, в том числе:

- Alibaba;
- Alipay;
- Tencent;
- WeChat;
- Poizon / Dewu.

Дополнительно используется:

```text
GEOIP,CN,DIRECT
```

### Google Core

`google_direct.list` содержит основные сервисы Google, которые должны работать напрямую:

- Google Search;
- Google Account;
- Gmail;
- Google Drive / Docs;
- Google Maps;
- CAPTCHA и системная инфраструктура.

YouTube намеренно **не относится к Google DIRECT** и обрабатывается отдельным PROXY-правилом с более высоким приоритетом.

### Остальные DIRECT

Также используются отдельные правила для:

- 2GIS;
- LAN / локальной сети.

# 🔵 PROXY

## YouTube

`youtube.list`

YouTube принудительно отправляется через VPN независимо от общих правил Google.

## Mobile Games

`mobile_game.list`

Используется для игр и связанных сервисов, которым требуется VPN для стабильной работы отдельных функций.

Правило располагается выше China / Google / GEOIP DIRECT, чтобы более общие правила не перехватывали игровой трафик.

---

# 🔴 REJECT

## Ads & Trackers

`ads.list`

Отдельный список используется для блокировки:

- рекламных доменов;
- web analytics;
- telemetry;
- известных tracking-сервисов.

Некоторые мобильные рекламные и attribution-сети намеренно могут быть исключены из блокировки, поскольку их блокирование способно нарушать работу rewarded ads и отдельных функций мобильных игр.

# 🌐 DNS

Конфигурация не полагается только на DNS интернет-провайдера.

Основные DNS:

```text
Google DoH
Cloudflare DoH
```

Fallback:

```text
Yandex DoH
Quad9 DoH
```

Используется:

```ini
hijack-dns = :53
```

Это позволяет Shadowrocket перехватывать обычные DNS-запросы на TCP/UDP 53 и обрабатывать их внутри конфигурации.

Системный DNS не используется как основной fallback:

```ini
dns-direct-system = false
dns-fallback-system = false
```

При проблемах с прямым DNS-запросом разрешается выполнить его через прокси:

```ini
dns-direct-fallback-proxy = true
```

---

# 🔐 Защита от DNS Leak

Для классических DNS-запросов используется:

```ini
hijack-dns = :53
```

Вместе с DoH это уменьшает вероятность того, что приложение сможет обойти настроенные DNS-серверы, просто отправив собственный запрос на порт `53`.

---

# 🏠 Локальная сеть

Локальные и служебные диапазоны исключены из обычной VPN-маршрутизации.

Используются:

```ini
skip-proxy
tun-excluded-routes
```

Это необходимо для нормальной работы:

- домашней локальной сети;
- роутера;
- локальных устройств;
- принтеров;
- multicast;
- captive portal;
- некоторых системных сервисов iOS.

---

# 🌐 IPv6

В текущей конфигурации IPv6 отключён:

```ini
ipv6 = false
prefer-ipv6 = false
```

Конфигурация ориентирована на предсказуемую IPv4-маршрутизацию.

По этой причине IPv6-сети в отдельных `RULE-SET` в данный момент не требуются.

---

# 📡 UDP

Если выбранный прокси-сервер не поддерживает UDP, используется:

```ini
udp-policy-not-supported-behaviour = REJECT
```

UDP в таком случае блокируется вместо незаметного перехода на `DIRECT`.

Это соответствует основной концепции **VPN-by-default** и предотвращает случайный обход VPN для UDP-трафика.

# 🔄 Автоматическое обновление правил

Большинство правил находится во внешних `.list` файлах и подключается через:

```text
RULE-SET
```

Файлы распространяются через jsDelivr:

```text
https://cdn.jsdelivr.net/gh/MyNicknme/shadowrocket-rules@main/
```

Изменения внутри `.list` не требуют ручного изменения основного конфига.

Для принудительного обновления можно использовать:

```text
Config → выбрать конфиг → Update
```

или:

```text
Force Update
```

---

# ⚠️ Изменение основного конфига

Важно различать обновление **правил** и обновление самого **`.conf`**.

Если изменилось только содержимое:

```text
rules/*.list
```

достаточно обновления `RULE-SET`.

Если изменились:

- `[General]`;
- DNS-настройки;
- порядок `RULE-SET`;
- добавлены новые списки;
- удалены старые списки;
- изменена общая логика маршрутизации,

необходимо обновить сам:

```text
VPN-by-default.conf
```

---

# ⚠️ Старые конфигурации

Ранее в репозитории присутствовали дополнительные варианты конфигурации, например:

```text
Only Blocked
```

Они больше **не поддерживаются и не обновляются**.

Вся дальнейшая разработка ведётся только для:

```text
VPN-by-default.conf
```

# 🛠 Принцип проекта

Конфигурация намеренно не использует огромные универсальные списки для каждого сервиса.

Основной подход:

> Чем меньше специальных правил — тем проще контролировать маршрутизацию.

Добавляются преимущественно те домены, IP и User-Agent, для которых есть практическая необходимость.

Более специфичные правила всегда располагаются выше общих.

Это позволяет сохранить конфигурацию понятной, предсказуемой и удобной для диагностики.
